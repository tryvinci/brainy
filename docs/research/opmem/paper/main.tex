\begin{abstract}
Retrieval benchmarks such as LoCoMo and LongMemEval measure whether an agent recalls
the right fact, but not whether a memory \emph{system} honors forget, correct, isolate,
and supersede semantics in production.
We present \textbf{OpMem v0}, a 13-task, pass/fail suite over neutral
\texttt{remember}/\texttt{recall}/\texttt{revise}/\texttt{forget} scripts with
substring-based assertions on ranked results.
On the frozen 2026-08-15 pin (git SHA \texttt{1b5ab3e}), Brainy passes \textbf{13/13}
via \texttt{GET /memories/search} while Mem0 \textbf{Platform} passes \textbf{10/13}
(failures: \texttt{cor02}, \texttt{sup03}, \texttt{upd02}).
This manuscript reports repository evidence, a reproducible protocol, threats to validity,
and new embedded-harness re-measurements on the current merge-pin git revision where completed.
We do \emph{not} claim conversational-recall superiority over Mem0; OpMem operational
leadership is orthogonal to LoCoMo J-scores.
\end{abstract}

\section{Introduction}
Production agents fail when suppressed memories leak after re-ingestion, corrections do not
stick, tenants bleed across isolation boundaries, or stale facts outrank updates.
Conversational QA benchmarks~\cite{maharana2024locomo,longmemeval2024} do not encode these
lifecycle contracts; hallucination-oriented memory benchmarks such as HaluMem~\cite{chen2025halumem}
focus on factual faithfulness rather than governed delete/correct semantics.

OpMem targets \textbf{operational correctness}: deterministic scripts, binary scoring, and
explicit adapter mappings to each system's native API surface~\cite{brainyopmem2026}.
Section~\ref{sec:limitations} lists threats; Section~\ref{sec:results} reports primary,
historical, and Phase~2 external-lane pins (Table~\ref{tab:external-lanes}).

\section{Related work}
\paragraph{Retrieval QA.}
LoCoMo~\cite{maharana2024locomo} and LongMemEval~\cite{longmemeval2024} score end-to-end
answer quality over long conversations; they are not substitutes for lifecycle tests.

\paragraph{Memory products.}
Mem0 documents accumulation-oriented designs and names staleness as an open problem~\cite{mem0state2026}.
We report Mem0 \textbf{Platform} numbers only on OpMem fixtures; we do not import Mem0 blog
LoCoMo percentages as same-pin scores.

\paragraph{External memory lanes (OpMem v0).}
Mem0 \textbf{Platform} on OpMem v0 is \textbf{completed} at negligible API volume (13 tasks, 47 scripted steps; Section~\ref{sec:external}).
Phase~2 counter-runs (after cost worksheet approval) are \textbf{completed} for Mem0 OSS, LangMem, Letta, and Zep; scores in Table~\ref{tab:external-lanes}: \textbf{9/13}, \textbf{8/13}, \textbf{5/13}, and \textbf{3/9$^{*}$} respectively (Zep raw harness \textbf{3/13}; \$0 paid).
Paid or vendor-hosted lanes require a written estimate before approval; that gate was not a categorical denial of spend.

\section{Task suite}
OpMem v0 comprises 13 JSON fixtures under \texttt{fixtures/opmem/}: three suppression,
three correction, three isolation, three staleness (including \texttt{upd03\_state\_supersession}),
and one idempotency task.
Assertions use case-insensitive substring checks on ranked \texttt{content} fields
(\texttt{min\_results}, \texttt{top\_contains}, \texttt{must\_exclude}, etc.).

\subsection{Cost-estimation plan (before any new paid run)}
\label{sec:cost-plan}
OpMem v0 has 13 tasks and 47 scripted steps (\texttt{fixtures/opmem/}). Before any new paid lane run, prepare billing and approval:
\begin{itemize}

\item \textbf{Mem0 OSS} --- Local Qdrant + \texttt{OPENAI\_API\_KEY}; ceiling \$1; dry-run projected OpenAI spend in worksheet.
\item \textbf{Zep} --- Zep Cloud free tier only (\$0 paid); cannot pin OpenAI models (product constraint recorded).
\item \textbf{Letta} --- Self-hosted App Server; ceiling \$1; no legacy Docker API or Letta Cloud paid plan.
\item \textbf{LangMem} --- Postgres/pgvector; ceiling \$1; no \texttt{InMemoryStore} on measured runs.
\end{itemize}
No dollar totals are asserted here until rate cards and deployment mode are pinned; approval requires the completed worksheet, not a categorical spend ban.

\section{Discussion}
OpMem failures on Mem0 align with accumulation-oriented update semantics:
corrections and durable forgets are not first-class lifecycle events.
Verbatim baseline passes 10/13, showing the suite discriminates rank-only stores from
governed suppression/correction.
Policy disagreements remain (\texttt{sup03} durable forget is a normative contract).

\section{Limitations}
\label{sec:limitations}
\begin{enumerate}
\item Small $n=13$; each task is $\sim$7.7\% of the aggregate score.
\item Substring scoring does not guarantee semantic safety.
\item Search vs \texttt{/recall} product path may diverge (lane ablation quantifies on Brainy).
\item English, domain-neutral fixtures; no concurrency or TTL tests.
\item Mem0 Platform API drift; Phase~2 OSS/LangMem/Letta/Zep pins are single-pass, small $n$. Zep forget fixtures are \emph{not supported} on the lane (Table~\ref{tab:external-lanes} footnote); publication line \textbf{3/9$^{*}$} vs raw harness \textbf{3/13}.
\item Fixture authorship bias; no independent external audit documented.
\end{enumerate}
